# 英雄热度接口

`GET /api/hero-votes` 为小程序提供小红书王者荣耀活动投票数据。活动 ID 固定为 `7694268422240177551`，只允许读取，不接收任意上游地址，不需要登录态、新环境变量、数据库迁移或定时任务。

## 数据流程

首次访问读取活动基础信息，再分批读取刺客、法师、辅助、射手、坦克、战士六组投票选项；有下一页时继续读取。每批并发两组，整轮限时 9 秒。全部成功且分类、票数、ID、分页与重复项校验通过后发布完整快照。任一组失败不发布部分榜单。

返回字段：

- `activityId`：源站活动 ID，保持字符串避免大整数精度丢失。
- `source`：活动来源名称和原始链接。
- `startedAt` / `fetchedAt`：本轮拉取开始、完成时间，UTC ISO 字符串。不同分类在一个短时间窗口内读取，不是源站原子快照。
- `cacheSeconds`：正常缓存时长 300 秒。
- `activityStatus`：源站活动状态原值。
- `total` / `rows`：投票选项数量及全部英雄。
- 每条英雄包括 `id`、`name`、`role`、`tabId`、`votes`、`sourceRank`。`sourceRank` 是源站职业分类排名；小程序全榜及分路排名自行按票数计算，同票并列。
- `stale` / `warning`：是否因刷新失败返回旧数据及提示。

## 缓存与故障

内存缓存与同实例请求合并减少重复上游调用，Vercel CDN 通过 `s-maxage` 共享完整响应。CDN 使用快照的剩余有效秒数，不在命中内存缓存后再延长五分钟。浏览器使用 `max-age=0`；客户端缓存也按 `fetchedAt` 判断有效期。筛选和排序在小程序本地完成，不因每次切换而请求源站。

刷新失败时，实例内存在 24 小时以内的成功快照就返回 `stale: true`，保留原时间并禁止 CDN 缓存此失败响应；没有可用快照时返回 502。失败后退避 30 秒。小程序也保留最近成功数据作为网络异常兜底，超过一天不再展示。

Serverless 实例重启或扩容后内存缓存可能丢失，跨实例不保证只有一次上游请求。无持久化意味着首次访问且源站异常时会显示错误状态；此方案不提供历史曲线、票数增量或永久快照。

## 发布与验证

1. 部署 `api/hero-votes.js` 及 `vercel.json` 新路由到现有 Vercel 项目。部署环境仍需能访问 `edith.xiaohongshu.com`，本机验证不等同于云端连通性。
2. 验证 `https://www.skinsdata.top/api/hero-votes` 返回 JSON、六个分类、真实 `fetchedAt` 和正常缓存标记。连续请求应在有效期内保留时间，过期后再更新。
3. 小程序运行 `node --test tests/hero-heat.test.js` 后用微信开发者工具编译、预览和真机检查。无需新增小红书 request 域名。

后端检查沿用 `npm run check`，其中自动包含 `test/hero-votes.test.js`。覆盖并发合并、缓存时间、分页、数据不完整、源站失败退避、超时与旧数据过期。

2026-10-12 本机真实请求验证：127 位英雄，六组数量分别为刺客 17、法师 29、辅助 21、射手 20、坦克 9、战士 31。这是验证时的观测值，代码未将英雄数量硬编码。

来源为活动页面使用的读取接口，不是有稳定性承诺的公开开发者 API；活动或接口变化时可能需要更新适配。
