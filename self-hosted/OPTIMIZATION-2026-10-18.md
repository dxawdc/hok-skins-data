# 新站与小程序优化

本轮实现位于本地，目标仍为独立站 `https://youtiao.fun/hokskins/` 与配套小程序。生产代码、Nginx 配置及小程序发布状态不因本地修改而改变。

## 行为

- 网页手动刷新为三个公开接口携带刷新版本，绕过此前四小时的浏览器缓存；常规重载继续复用会话缓存。
- 网页与小程序均不再把公开目录当成删除拥有/关注标记的依据。旧缓存、短暂缺失、改名不会自动生成删除操作。
- 小程序区分新鲜缓存与离线旧缓存；进入前台时检查过期时间，失败后至少间隔一分钟重试。五个主页面支持刷新，重复刷新五秒内合并/限制，活动页面订阅数据更新并在卸载后取消订阅。
- 手机网页搜索框独占一行，筛选显示完整标签；统计区分记录数和去重皮肤数。底栏保留皮肤、英雄、资源、我的，其他入口归入“更多”。小程序品质与拥有筛选可展开。

## 成本边界

`public-cache.cjs` 仅缓存三个无鉴权、无 Cookie、无分页的完整公开接口。使用现有 Node 进程，不增加 Redis、机器或付费服务。

- 三个键共享 12 MiB 正文预算，正常保留 60 秒；同一路由的并发读取合并为一次查询。
- 手动刷新最多每五秒重新读取一次，刷新参数不增加缓存键数；刷新响应不存入浏览器 HTTP 缓存。
- 成功的后台写入使缓存失效。写入前已开始的请求不能重新填入旧缓存。直接 SQL 更新最多等待进程缓存过期，需即时展示时重启独立服务或手动刷新。
- ETag 支持 304；错误不作为成功数据缓存；登录、用户和带凭据请求绕过共享缓存。
- 图片沿用六种预生成尺寸，240 映射到 320，避免为卡片读取原图。已有文件按修改时间生成版本，版本索引最多 4096 项、有效一分钟，上传后清除。无版本图片缓存一小时，有版本图片缓存 30 天；不对用户私有头像应用这些策略。

这是降低重复查询和传输的方案，不能直接推导月费下降金额；固定服务器费用不会因缓存自动变化。上线后应结合真实访问量、CPU、内存、出网账单判断是否还有必要调整规格。

## 发布准备（尚未执行）

1. 重新读取并备份 `/opt/hokskins/app/server.cjs`、`lib/image-store.cjs`、`public/index.html` 及两份 Nginx 图片配置，核对与检查过的源版本一致。
2. 用 `prepare-public.py <当前 index.html> <候选 index.html>` 生成前台。用 `prepare-performance.py <当前 server.cjs> <候选 server.cjs>` 生成服务器入口。两个脚本支持重复执行，遇到未知必要锚点会拒绝修改。不要用旧站根目录 HTML 覆盖独立站的 API 与用户适配。
3. 配套安装 `public-cache.cjs`、`image-store.cjs` 到独立 app 的 `lib/`，以及候选入口、HTML；同时更新 `nginx-image-variants.conf` 与 `nginx-image-location.conf`，后者依赖前者定义的变量。
4. 执行 `node --check` 和 `nginx -t`，平滑重载 Nginx，只重启 `hokskins-web.service`。不重启或修改 GDN 服务。
5. 公网验证 833 款/1555 条（或发布时的更新值）、两款新增皮肤、手机搜索/更多导航、公开接口 MISS/HIT/304、带版本图片缓存头、登录/标记接口不被缓存，并检查最近错误日志。
6. 小程序重新编译验收后，按项目流程另行上传/发布。网页部署不代表小程序已发布。

回滚须成组恢复服务器入口、缓存/图片模块及两份 Nginx 配置，再校验并仅重启独立服务。此次优化不涉及数据库结构或业务数据迁移。

本地回归：网页仓库 `npm run check`；小程序 `node --test tests/*.test.js`。浏览器、独立服务入口与并发验证记录保存在工作区 `output/review-20261018/`。
